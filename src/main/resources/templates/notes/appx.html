부록 A. 계산 공식 · 풀이 🧮

계산 문제는 공식 → 답안 절차 → 풀이 예제를 한곳에서 보도록 이 부록에 모았다. A-1 ~ A-16 은 유형별 공식과 풀이이고, A-17 은 본문 곳곳의 계산 예제를 찾아가는 색인이다. 풀이는 접혀 있으니 먼저 손으로 풀어 본다.

A-1. CPU 스케줄링 (Part 1-4)

대기 시간(Waiting Time)   = 시작 시간 - 도착 시간
반환 시간(Turnaround Time) = 종료 시간 - 도착 시간
응답 시간(Response Time)   = 최초 CPU 할당 시간 - 도착 시간
반환 시간 = 대기 시간 + 실행 시간   ← 검산용

A-2. 은행원 알고리즘 (Part 1-6)

Available = 전체 자원 - Σ(각 프로세스의 Allocation)
Need = Max - Allocation   (문제가 Need를 직접 주면 그대로 사용)
프로세스 종료 시 반납량 = 원래 Allocation + 그 사이 새로 받은 양

A-3. 페이지 주소 변환

논리 주소 = [ 페이지 번호 p | 오프셋 d ]
페이지 크기 = 2ⁿ  →  오프셋 d = n비트
논리 주소 공간 = 2ᵐ  →  페이지 번호 p = (m - n)비트
페이지 테이블 항목 수 = 2^(m-n)
물리 주소 = 프레임 번호(f) × 페이지 크기 + 오프셋(d)

답안 3줄: ① 분할(하위 n비트 = 오프셋 d, 나머지 = 페이지 번호 p) ② 조회(PT[p] = 프레임 f) ③ 결합(물리 주소 = f ‖ d, 비트열 끝까지 쓰기)

예제 1 (2진수) 16비트 논리 주소, 페이지 4KB. 논리 주소 0011 1010 0111 1111, PT[3] = 5일 때 물리 주소는?

풀이
  • 4KB = 2¹² → 오프셋 12비트, 페이지 번호 16 − 12 = 4비트
  • p = 0011 = 3, d = 1010 0111 1111
  • PT[3] = 5 = 101
  • 물리 주소 = 101 ‖ 1010 0111 1111 = 101 1010 0111 1111 (= 0x5A7F = 23167)

예제 2 (10진수) 페이지 1KB, 논리 주소 5000, PT[4] = 7일 때 물리 주소는?

풀이
  • p = 5000 ÷ 1024 = 4 (몫), d = 5000 − 4 × 1024 = 904 (나머지)
  • 물리 주소 = 7 × 1024 + 904 = 8072

예제 3 (테이블 크기) 32비트 주소, 페이지 4KB, 페이지 테이블 항목(PTE) 4바이트일 때 프로세스당 페이지 테이블 크기는?

풀이
  • 페이지 번호 = 32 − 12 = 20비트 → 항목 2²⁰개
  • 2²⁰ × 4B = 4MB → 그래서 다단계 페이지 테이블·역페이지 테이블을 쓴다

예제 4 (페이지화된 세그먼테이션) 논리 주소 = 세그먼트 번호 | 페이지 번호 | 변위. 세그먼트 4, 페이지 2, 변위 11이고 세그먼트 4의 페이지 테이블이 [5, 2, 1, 6]이면?

풀이
  • 세그먼트 번호 = 몇 번째 페이지 테이블을 쓸지 → 세그먼트 4의 테이블 선택
  • 그 테이블의 2번 항목 = 프레임 1, 변위는 그대로 11

비트 단위 주소 변환 풀이 절차 🔥 🧮

문제: 16비트 논리 주소, 페이지 크기 4KB, 페이지 테이블이 주어짐

① 오프셋 비트 수 = log₂(페이지 크기) = log₂(4096) = 12비트
② 페이지 번호 비트 = 16 - 12 = 4비트  → 페이지 0~15 (테이블 16칸과 일치하는지 검산)
③ 논리 주소를 [상위 4비트 | 하위 12비트] 로 자른다   (아래는 설명용 임의 값)
      0111 | 0000 1010 0001
      p = 0111₂ = 7
④ 페이지 테이블[7]의 프레임 번호를 읽는다 (예: 테이블에 101이 적혀 있다면)
⑤ 물리 주소 = [프레임 번호 | 오프셋 그대로]
      101 | 0000 1010 0001   → 15비트 물리 주소

⚠️ 함정: 오프셋은 절대 바뀌지 않는다. 물리 주소의 비트 수 = 프레임 번호 비트 + 오프셋 비트 → 논리 주소와 길이가 다를 수 있다. 프레임 번호를 3비트로 줬으면 물리 주소는 15비트다.

A-4 vs A-5. TLB 접근시간과 캐시 접근시간은 무엇이 다른가

A-4. TLB 유효 접근시간 A-5. 캐시 평균 접근시간
캐시하는 것 주소 변환 정보(페이지 테이블 항목) 데이터 자체
미스 시 추가 비용 페이지 테이블을 읽으러 메모리 1번 더 → t + 2m 데이터를 가지러 메모리 → Tc + Tm
히트 시 t + m (변환 후 데이터는 어차피 메모리에서) Tc만
쓰기 정책 해당 없음 write-through / write-back에 따라 쓰기 시간이 다름

한 줄: TLB는 "어디 있는지"를, 캐시는 "무엇인지"를 기억한다. TLB 히트여도 데이터는 메모리에서 읽는다(캐시가 없다면).

A-4. TLB 유효 접근시간(EAT)

EAT = h × (t + m) + (1-h) × (t + 2m)
  h = TLB 히트율, t = TLB 접근시간, m = 메모리 접근시간
※ TLB 접근시간을 무시하라는 조건이면: EAT = (2 - h) × m

예제 TLB 20ns, 메모리 100ns, TLB 히트율 80%일 때 EAT는? TLB 시간을 무시하면?

풀이
  • 히트: 20 + 100 = 120, 미스: 20 + 100 + 100 = 220
  • EAT = 0.8 × 120 + 0.2 × 220 = 96 + 44 = 140ns
  • TLB 무시: (2 − 0.8) × 100 = 120ns

A-5. 캐시 평균 접근시간

읽기 동작 시간 = Hit비율×캐시시간 + Miss비율×(캐시시간+메모리시간)

[Write-through] 쓰기 동작 시간 = 캐시시간 + 메모리시간   ← 히트율과 무관, 항상 고정!
[Write-back]     쓰기 동작 시간 = Hit비율×캐시시간 + Miss비율×(캐시시간+메모리시간)

평균 접근시간 = 읽기비율 × 읽기시간 + 쓰기비율 × 쓰기시간
가정 읽기 miss write-through 쓰기 예제 평균 (Tc 10, Tm 100, h 0.9, 읽기 80%)
순차 접근(캐시 확인 후 메모리) Tc + Tm = 110 Tc + Tm = 110 0.8 × 20 + 0.2 × 110 = 38ns
동시 접근(병렬) Tm = 100 Tm = 100 0.8 × 19 + 0.2 × 100 = 35.2ns
  • 🔥 읽기와 쓰기에 같은 가정을 쓰고, 답안 첫 줄에 가정을 명시한다.
🧮 평균 접근시간(EAT) 계산

조건: 주기억장치 접근 100ns, 캐시 접근 10ns, 읽기 80% / 쓰기 20%, 캐시 히트율 90%, Write-through 정책

① 읽기 동작 시간

읽기는 Hit/Miss에 따라 다름:
  Hit(90%)  : 캐시만 읽으면 됨          → 10ns
  Miss(10%) : 캐시 확인 + 주기억장치까지 → 10 + 100 = 110ns

읽기 동작 시간 = 0.9 × 10 + 0.1 × 110
             = 9 + 11 = 20ns

② 쓰기 동작 시간

Write-through는 Hit이든 Miss든 "항상 주기억장치에도 써야" 한다.
→ Hit/Miss 여부와 무관하게 항상 캐시(10) + 주기억장치(100)

쓰기 동작 시간 = 10 + 100 = 110ns

⚠️ 최대 함정: 쓰기에서도 히트율(90%)을 곱하는 실수를 매우 많이 한다. Write-through의 정의 자체가 "항상 메모리에 같이 쓴다"이므로, 쓰기는 히트율과 무관하게 캐시+메모리 시간이 고정으로 더해진다.

③ 평균 접근 시간

평균 접근시간 = (읽기 비율 × 읽기시간) + (쓰기 비율 × 쓰기시간)
             = 0.8 × 20 + 0.2 × 110
             = 16 + 22 = 38ns

✅ 답: 읽기 20ns / 쓰기 110ns / 평균 38ns

Write-back이었다면? (비교로 함께 알아둘 것)

쓰기 동작 시간 = Hit(90%): 캐시만(10ns) + Miss(10%): 캐시확보 위해 read 필요(10+100=110ns)
             = 0.9×10 + 0.1×110 = 9+11 = 20ns   ← write-through(110ns)보다 훨씬 빠름

이것이 Write-back이 "쓰기 속도가 빠르다"고 서술하는 근거의 실제 계산이다.

A-6. 서브네팅

사용 가능 호스트 수 = 2^(호스트 비트 수) - 2   ← 네트워크 주소, 브로드캐스트 주소 제외
서브넷 개수 = 2^(빌려온 비트 수)

예제 1 (같은 크기로 나누기) 192.168.10.0/24를 4개의 같은 서브넷으로 나누면?

풀이
  • 4 = 2² → 2비트 빌림 → /26, 마스크 255.255.255.192, 블록 64
  • .0~.63 / .64~.127 / .128~.191 / .192~.255, 각 사용 가능 호스트 62

예제 2 (주소가 속한 서브넷 찾기) 200.1.1.77/27의 네트워크 주소, 브로드캐스트 주소, 사용 범위는?

풀이
  • /27 → 블록 32 → 0, 32, 64, 96 … → 77은 64~95
  • 네트워크 200.1.1.64, 브로드캐스트 200.1.1.95, 호스트 .65 ~ .94 (30개)
  • 검산: 77 AND 224 = 0100 1101 AND 1110 0000 = 0100 0000 = 64

예제 3 (VLSM) 210.11.21.0/24에서 호스트 100, 50, 10개 서브넷을 효율적으로 만들면?

풀이
요구 블록 접두사 마스크 네트워크 주소 사용 가능
100 128 /25 .128 210.11.21.0 126
50 64 /26 .192 210.11.21.128 62
10 16 /28 .240 210.11.21.192 14
  • 큰 블록부터 배정. 10개짜리를 /27(32)로 잡으면 "효율적"이 아님.

🧮 서브네팅 계산

/24 = 255.255.255.0 → 호스트 비트 8개 → 2^8 = 256개
사용 가능 호스트 수 = 2^(호스트 비트) - 2
                     (-2: 네트워크 주소, 브로드캐스트 주소 제외)

예) 192.168.1.0/26
   → 호스트 비트 = 32 - 26 = 6
   → 서브넷당 주소 256/4 = 64개, 사용 가능 호스트 = 2^6 - 2 = 62개
   → 서브넷: .0~.63 / .64~.127 / .128~.191 / .192~.255
   → 첫 서브넷의 네트워크 주소 = .0, 브로드캐스트 = .63, 사용 범위 = .1 ~ .62

⚠️ 함정: -2 하는 것을 잊지 말 것. 그리고 서브넷 개수는 2^(빌린 비트 수)다.

VLSM (가변 길이 서브넷 마스크) 할당 🧮

공식: (필요 호스트 수 + 2) ≤ 2^h   → 호스트 비트 h, 마스크 = /(32 - h)
      +2 = 네트워크 주소 + 브로드캐스트 주소

절차: ① 요구가 큰 서브넷부터 정렬 ② 블록 크기 2^h 를 앞에서부터 연속 배치
      ③ 각 블록: 첫 주소(네트워크 주소) / 사용 가능 호스트 = 2^h - 2

예) (설명용) 192.168.10.0/24 를 60 · 25 · 5 호스트로
   60 →  62 ≤  64 → h=6 → /26 (255.255.255.192) → 192.168.10.0   , 호스트 62개
   25 →  27 ≤  32 → h=5 → /27 (255.255.255.224) → 192.168.10.64  , 호스트 30개
    5 →   7 ≤   8 → h=3 → /29 (255.255.255.248) → 192.168.10.96  , 호스트 6개
   (210.11.21.0/24 · 100/50/10 은 같은 절차로 직접 풀어볼 것)

⚠️ 함정: "첫 번째 IP주소"가 네트워크 주소를 뜻하는지 첫 사용 가능 호스트 주소(+1)를 뜻하는지 답안에 명시한다. 둘 다 써 두면 안전하다.

A-7. TCP 순서 번호(SEQ) / 확인 번호(ACK)

ACK 번호 = 상대방이 보낸 SEQ 번호 + 수신한 데이터 크기
         = "다음에 받기를 기대하는 바이트 번호"
규칙 내용
각 호스트는 자기만의 번호 공간 A의 번호와 B의 번호는 무관
시작 번호(ISN) 🎲 무작위 — 번호 예측 공격(IP 스푸핑) 방지, 이전 연결의 지연 패킷과 혼동 방지
ACK 📏 상대가 보낸 SEQ + 상대가 보낸 길이 = "다음에 받을 바이트 번호"
번호 소비 SYN·FIN = 1, 데이터 = 바이트 수, 순수 ACK = 0

예제 1 A의 ISN 100, B의 ISN 300, 연결 후 A가 4바이트, B가 4바이트를 보내면 각 세그먼트의 SEQ·ACK는?

풀이
단계 방향 내용 SEQ ACK
① A → B SYN 100 🎲 —
② B → A SYN+ACK 300 🎲 101
③ A → B ACK 101 301
④ A → B 데이터 4B 101 (③은 0 소비) 301
⑤ B → A 데이터 4B 301 105
⑥ A → B ACK 105 305

🧮 빈칸 채우기

문제: A → B SYN=23, data='C' / B → A [?]=[?], [?]=[?], data='C' / A → B ACK=21 ('C'는 1Byte)

풀이 원리

ACK 번호 = 상대방으로부터 받은 SEQ + 받은 데이터 크기(1Byte)

역산으로 B의 SYN 값 구하기

마지막에 A가 보낸 ACK = 21
21 = (B의 SYN 값) + 1
→ B의 SYN = 20

B가 보낼 ACK 값 구하기

A로부터 SYN=23, data 1Byte 수신
→ ACK = 23 + 1 = 24

✅ 답: SYN = 20, ACK = 24

검증: A의 최종 ACK가 20 + 1 = 21로 문제에 주어진 값과 일치 ✓ 답안 작성 팁: "ACK 번호는 상대의 시퀀스 번호에 수신한 크기를 더한 값, 즉 다음에 받기를 기대하는 바이트 번호"라는 원리를 함께 서술할 것.

  • 그림에 데이터와 함께 "SYN=23"처럼 적혀 있으면 SYN 플래그가 아니라 순서 번호(Seq)를 뜻하는 출제 표기로 보고, 답안에 가정을 한 줄 쓴다.

A-8. 시간복잡도 증가 순서 (Part 5-1)

O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)

Quick Sort : 평균 O(n log n)  /  최악 O(n²)  (피벗이 항상 최댓값·최솟값일 때)
Merge Sort : 최선=평균=최악 모두 O(n log n)  (항상 절반씩 균등 분할)

A-9. 해시 탐사 공식 (Part 5-3)

선형 탐사(Linear Probing)   : (h(k) + i)  % m
제곱 탐사(Quadratic Probing) : (h(k) + i²) % m

A-10. 그래프 알고리즘 시간복잡도 (Part 5-4)

Prim           : O(E log V)   (우선순위 큐 사용 시), 조밀 그래프에 유리
Kruskal        : O(E log E)   (정렬이 지배적), 희소 그래프에 유리
Dijkstra       : O(E log V)   (우선순위 큐 사용 시), 음수 가중치 불가
Bellman-Ford   : O(V × E)     음수 가중치 허용, 음수 사이클 탐지 가능
Floyd-Warshall : O(V³)        모든 정점 쌍 최단경로, 음수 가중치 허용(음수 사이클 불가)

A-11. 순열 · 조합 · GCD/LCM (Part 5-6)

순열 nPr = n! / (n-r)!
조합 nCr = n! / (r! × (n-r)!)
유클리드 호제법: gcd(a,b) = gcd(b, a % b)      시간복잡도 O(log(min(a,b)))
lcm(a,b) = a × b / gcd(a,b)

A-12. 정수 표현 · 보수

1의 보수 = (2ⁿ − 1) − x   (모든 비트 반전)
2의 보수 = 2ⁿ − x         (반전 + 1)
n비트 2의 보수 범위 = −2ⁿ⁻¹ ~ 2ⁿ⁻¹ − 1
unsigned 오버플로 = MSB 밖으로 carry
signed 오버플로   = 부호 같은 두 수의 합의 부호가 다름

예제 1 (표현법) 8비트로 −5를 부호-크기, 1의 보수, 2의 보수로 나타내면? 각 표현의 범위는?

풀이
표현 −5 범위 (8비트) 0의 표현
부호-크기 1000 0101 −127 ~ +127 +0, −0 두 개
1의 보수 1111 1010 (전부 반전) −127 ~ +127 +0, −0 두 개
2의 보수 1111 1011 (반전 + 1) −128 ~ +127 하나
  • 2의 보수 → 10진: 1111 1011 = −128 + 64 + 32 + 16 + 8 + 2 + 1 = −5 (MSB 자리값을 음수로)

예제 2 (오버플로) 8비트 0110 0100(100) + 0101 0000(80)은?

풀이
  • 합 = 1011 0100, 자리올림(Carry) 없음
  • unsigned로 보면 180 → 정상
  • signed(2의 보수)로 보면 양수 + 양수인데 부호 비트가 1 → −76, 오버플로

예제 3 (Carry ≠ Overflow) 8비트 1111 0000(−16) + 0001 0001(17)은?

풀이
  • 합 = 1 0000 0001 → Carry 1 발생, 8비트 결과 0000 0001
  • unsigned: 240 + 17 = 257 → unsigned 오버플로(Carry로 판단)
  • signed: −16 + 17 = 1 → 오버플로 아님 (부호가 다른 두 수의 합은 오버플로가 없다)

예제 4 (unsigned 언더플로) C에서 unsigned char x = 0; x = x - 1; 이후 x는?

풀이
  • 0 − 1 → 2⁸ − 1 = 255 (모듈로 2⁸로 감김, Wrap-around)
  • for (unsigned i = n; i >= 0; i--)는 i가 음수가 될 수 없어 무한 루프

"~에 대해 기술/설명/정의하시오"는 항상 이 3단으로 쓴다.

단계 쓸 내용 예: SYN Flooding

원인 왜 생기는가 / 왜 필요한가 / 어떻게 동작하는가 서버는 SYN마다 반개방 연결을 저장하고 ACK를 기다리는데, 출발지가 위조라 ACK가 오지 않음
해결/비교 문제 현상이면 해결책 2~4개, 개념이면 비교표 SYN 쿠키, 타임아웃 단축, 백로그 확대, 방화벽 임계치
