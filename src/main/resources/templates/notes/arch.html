주요 레지스터

레지스터 역할
PC (Program Counter) 다음에 실행할 명령어의 주소
IR (Instruction Register) 현재 가져온(fetch한) 명령어
MAR (Memory Address Register) 메모리에 접근할 주소
MBR/MDR (Memory Buffer/Data Register) 메모리와 주고받을 데이터
AC (Accumulator) 연산 중간 결과 저장
SP (Stack Pointer) 스택의 최상단 주소

Instruction Cycle (명령어 사이클) 🔥

┌────────┐    ┌────────┐    ┌─────────┐    ┌─────────┐
│ Fetch  │───►│ Decode │───►│ Execute │───►│ Store /  │──┐
│(인출)   │    │(해독)   │    │ (실행)   │    │Writeback │  │
└────────┘    └────────┘    └─────────┘    └─────────┘  │
     ▲                                                    │
     └──────────── 다음 명령어로 (PC 증가) ──────────────────┘
                          │
                 (인터럽트 확인은 매 사이클 끝에서)
  1. Fetch: PC가 가리키는 주소의 명령어를 메모리에서 IR로 가져옴. PC 증가
  2. Decode: 명령어를 해석하여 어떤 연산인지, 오퍼랜드는 무엇인지 판단
  3. Execute: ALU가 실제 연산 수행
  4. Store(Writeback): 결과를 레지스터나 메모리에 저장

이 사이클이 끝날 때마다 CPU는 인터럽트 발생 여부를 확인한다. (1장 Interrupt와 연결)

🔥 RISC vs CISC (어셈블리 코드로 판단)

항목 RISC (Reduced Instruction Set Computer) CISC (Complex Instruction Set Computer)
명령어 개수 적음, 단순함 많음, 복잡함
명령어 길이 고정 길이 가변 길이
명령어당 실행 1 클록에 1개 (파이프라이닝에 최적) 명령어마다 여러 클록 소요
실행 방식 Load/Store 구조 — 연산은 레지스터끼리만, 메모리 접근은 Load/Store 명령만 담당 메모리를 직접 피연산자로 사용 가능
하드웨어 단순 (제어 로직이 하드와이어드) 복잡 (마이크로코드로 명령어 해석)
컴파일러 부담 큼 (복잡한 연산을 여러 단순 명령어로 쪼개야 함) 작음 (하드웨어가 복잡한 연산을 한 번에 처리)
코드 길이 김 (명령어 수 많음) 짧음
전력 소모 적음 많음
대표 예 ARM, RISC-V, 옛 SPARC/MIPS x86/x86-64 (Intel, AMD)

어셈블리 코드로 구별하는 방법

x86-64 (CISC) 예시:
  mov  DWORD PTR [rbp-4], 1     ← 메모리에 직접 값을 저장(mov가 메모리 오퍼랜드 직접 다룸)
  add  eax, edx                 ← 레지스터 연산

ARM (RISC) 예시:
  movs r3, #1
  str  r3, [r7, #12]            ← 레지스터 값을 메모리에 "따로" 저장(str/ldr 명령 분리)
  ldr  r3, [r7, #8]             ← Load 전용 명령어 존재
  adds r3, r3, r2                ← 반드시 레지스터끼리만 연산

판별 포인트: 메모리 접근 명령(ldr/str, Load/Store)이 연산 명령과 분리되어 있고 레지스터끼리만 연산하면 → RISC(ARM). mov, add 등이 메모리 주소를 직접 오퍼랜드로 받으며 섞여 쓰이면 → CISC(x86).

장단점 요약 - RISC 장점: 파이프라이닝 효율 ↑, 설계 단순, 전력 효율 ↑ (모바일에 적합) / 단점: 코드 크기 증가, 컴파일러 최적화 의존도 높음 - CISC 장점: 적은 명령어로 복잡한 작업 수행(코드 밀도 ↑), 어셈블리 작성 편의 / 단점: 파이프라이닝 어려움, 하드웨어 복잡·전력 소모 큼

계층 구조가 성립하는 원리 = 지역성(Locality of Reference)

지역성 설명 활용
시간적 지역성 (Temporal) 최근 접근한 데이터는 곧 다시 접근될 가능성이 높다 캐시에 최근 사용 데이터 유지 (LRU)
공간적 지역성 (Spatial) 접근한 주소에 인접한 주소도 곧 접근될 가능성이 높다 캐시가 블록(라인) 단위로 한꺼번에 가져옴

지역성이 성립하기 때문에, 작고 빠른 캐시에 "자주 쓰는 것만" 올려도 적중률(Hit Ratio)이 높게 유지된다. 이게 메모리 계층 구조 전체의 존재 이유다.

Write Policy — Write-through vs Write-back

write-through                    write-back
  CPU                              CPU
   │                                │
   │──────►┌──────┐                 │──────►┌──────┐
   │       │ 캐시  │                 │       │ 캐시  │
   │       └──┬───┘                 │       └──┬───┘
   │          │ (항상 같이 씀)         │          │ (일단 캐시만 갱신,
   ▼          ▼                     │          │  Dirty bit 표시)
┌──────────────┐                    │          ▼
│   주기억장치   │                    │      ┌──────────────┐
└──────────────┘                    └─────►│   주기억장치   │
                                    (교체 시점에만 몰아서 씀)  └──────────────┘
항목 Write-through Write-back
정의 캐시에 쓸 때 주기억장치에도 즉시 함께 기록 캐시에만 쓰고, 해당 블록이 교체될 때(축출 시) 비로소 주기억장치에 반영
필요 요소 없음 Dirty Bit(수정 비트) — 수정 여부 표시
일관성 항상 일치(메모리가 항상 최신) 교체 전까지는 불일치 상태 존재
쓰기 속도 느림 (매번 메모리 접근) 빠름 (캐시에만 쓰면 끝)
메모리 트래픽 큼 (매 쓰기마다 발생) 적음 (실제 축출될 때만)
멀티코어 일관성 상대적으로 유리 (항상 최신) 별도의 캐시 일관성 프로토콜 필요(MESI 등)
장애 시 안전성 안전 (메모리가 항상 최신이라 데이터 손실 적음) 전원 손실 시 미반영 데이터 유실 위험

↗ 부록 A · 평균 접근시간(EAT) 계산

Write Miss 정책 (참고) △

정책 설명

No-write-allocate 캐시를 거치지 않고 주기억장치에 바로 씀 (Write-through와 자주 결합)

4-4. 데이터 표현 ⭐

고정소수점 vs 부동소수점

고정소수점 (Fixed-point) 부동소수점 (Floating-point)
구조 소수점 위치 고정 부호 + 지수부(Exponent) + 가수부(Mantissa)
표현 범위 좁음 매우 넓음
정밀도 일정 값의 크기에 따라 정밀도가 달라짐(큰 수일수록 오차 커짐)
연산 속도 빠름, 하드웨어 단순 느림(별도 FPU 필요), 복잡
오차 없음(정수 범위 내 정확) 반올림 오차 발생 가능 (0.1을 정확히 표현 못 함 등)
용도 임베디드, 정수 연산 중심 과학 연산, 그래픽, 딥러닝

IEEE 754 (32비트 단정도): [부호 1비트][지수 8비트][가수 23비트]

패리티 비트 vs 해밍 코드

패리티 비트 (Parity Bit) 해밍 코드 (Hamming Code)
목적 오류 검출만 가능 오류 검출 + 정정 가능
원리 1의 개수를 짝수/홀수로 맞추는 비트 1개 추가 여러 개의 패리티 비트를 특정 위치(2의 거듭제곱 위치)에 배치해 오류 위치까지 특정
한계 2비트 오류는 검출 불가(짝수 개 오류 시 패리티가 우연히 맞음), 오류가 어디인지는 모름 계산 및 저장 공간 오버헤드가 더 큼
용도 간단한 전송 오류 검출 (시리얼 통신 등) ECC 메모리, 저장장치 등 정정이 필요한 곳

정수 표현 — 부호-크기 / 1의 보수 / 2의 보수 🔥

(n비트) 부호-크기 1의 보수 2의 보수
음수 만드는 법 최상위 비트(MSB)만 1 모든 비트 반전 비트 반전 + 1
같은 식 – (2ⁿ − 1) − x (4비트: 1111 − x) 2ⁿ − x (4비트: 10000 − x)
0의 표현 +0, −0 두 개 +0, −0 두 개 하나뿐
범위 (4비트) −7 ~ +7 −7 ~ +7 −8 ~ +7
뺄셈 별도 회로 필요 덧셈 + 끝자리 올림(end-around carry) 처리 덧셈 회로 그대로 (A − B = A + B의 2의 보수)

2의 보수를 쓰는 이유: ① 뺄셈을 덧셈 회로로 처리해 하드웨어가 단순 ② 0이 하나라 비교가 단순 ③ 표현 범위가 하나 더 넓다.

⚠️ 예외: 0000의 2의 보수 = 1111 + 1 = 1 0000 → 변환 단계에서 생긴 carry는 버려 0000이 된다.

2진 덧셈 · Carry vs Overflow 🔥 🧮

기준 판정 예: 1111 + 0001
unsigned (부호 없음) MSB 밖으로 carry가 나가면 범위 초과 15 + 1 = 16 → 오버플로 (1 0000)
signed (2의 보수) 부호가 같은 두 수를 더했는데 결과 부호가 다름 = MSB로 들어온 carry ≠ MSB에서 나간 carry (−1) + 1 = 0 → 오버플로 아님

⚠️ 함정: 문제가 "4비트를 초과하는 경우 오버플로"라고 정의하면 unsigned 기준(carry 발생)으로 판단한다. signed/unsigned를 섞으면 오답이다. 문제 읽기 함정 (실제 오답): 최종 결과를 출력 형식(예: 대문자 테이블)으로 변환하라는 조건을 놓치지 말 것. 오버플로일 때만 carry 포함 2진수를 그대로 출력하는 식의 예외 규칙을 표시해 두고 푼다.

unsigned 언더플로 (Wrap-around) 🔥

unsigned int i;
for (i = 100; i >= 0; )
    printf("%u\n", --i);
  • --i는 전위 감소 → 출력은 99, 98, …, 1, 0
  • i가 0일 때 --i → unsigned는 음수가 없으므로 최댓값 4,294,967,295 (2³² − 1)로 순환
  • i >= 0은 unsigned에서 항상 참 → 무한 루프 (99부터 0까지 출력 후 4294967295, 4294967294, … 계속)
  • 답안 핵심: "unsigned 자료형은 0 미만을 표현할 수 없어 조건식이 항상 참이 되고, 0에서 감소하면 모듈러 연산으로 최댓값으로 돌아간다"
  • 해결: 조건을 i > 0으로 바꾸거나 signed int 사용

소수점이 있는 2진수 ↔ 10진수 🧮

자릿값: … 2²  2¹  2⁰ . 2⁻¹  2⁻²  2⁻³ …
              4   2   1    0.5  0.25  0.125

100110.110₂ = 32 + 4 + 2  +  0.5 + 0.25  = 38.75
  • 역방향(10진 소수 → 2진): 소수부에 2를 곱하고 정수부를 떼어내기를 반복. 0.75 → 1.5(1) → 1.0(1) → 0.11₂
  • 0.1처럼 2진수로 무한소수가 되는 값이 있다 → IEEE 754 부동소수점의 반올림 오차 원인
  • 답안에는 자리별 가중치 × 비트 값의 합을 표로 써야 과정 점수를 받는다

4-5. RAID ⭐

개념: 여러 개의 물리 디스크를 하나의 논리 장치처럼 묶어, 성능 향상 또는 데이터 안정성(중복성) 을 확보하는 기술.

RAID 레벨 방식 최소 디스크 특징
RAID 0 스트라이핑(데이터를 여러 디스크에 분산 저장) 2 속도 최고, 중복 없음 → 디스크 1개만 고장나도 전체 데이터 손실
RAID 1 미러링(동일 데이터를 여러 디스크에 복제) 2 안정성 높음, 읽기 속도 향상. 용량 효율 50%(절반이 복사본)
RAID 4 스트라이핑 + 전용 패리티 디스크 1개 3 패리티가 한 디스크에 몰려 병목(bottleneck) 발생
RAID 5 스트라이핑 + 패리티를 모든 디스크에 분산 저장 3 RAID 4의 병목 해결. 디스크 1개 고장까지 복구 가능. 널리 사용
RAID 6 RAID 5 + 패리티를 이중으로 분산 4 디스크 2개까지 동시 고장 복구 가능. 안정성 최고, 쓰기 성능은 더 낮음

🔥 RAID 5 vs RAID 6 그림 판별

문제의 A방식: 패리티가 parity A → Disk4, parity B → Disk3, parity C → Disk2, parity D → Disk1처럼 디스크마다 돌아가며 한 줄에 1개 → RAID 5

문제의 B방식: 한 줄(스트라이프)에 parity 1과 parity 2, 두 개가 분산 → RAID 6

(패리티가 한 디스크에 몰려 있었다면 RAID 4)

B방식(RAID 6)이 A방식(RAID 5) 대비 갖는 장점

  • 스트라이프마다 서로 독립적인 패리티 2개(P = 전체 XOR, Q = 리드-솔로몬 가중합)를 두므로 디스크 2개가 동시에 고장 나도 복구할 수 있다(식 2개 → 미지수 2개). RAID 5는 1개까지만.
  • 대용량 디스크는 고장 디스크를 재구축하는 시간이 길어, 그사이 두 번째 디스크가 고장 나는 위험이 크다 → RAID 6이 이를 견딘다.
  • 대가: 패리티를 두 번 계산해 쓰기 성능 저하, 사용 용량 n − 2(RAID 5는 n − 1).

패리티로 복구하는 원리: 패리티 = 같은 줄 데이터의 XOR. 디스크 하나가 고장 나면 남은 데이터와 패리티를 XOR해 잃어버린 블록을 복원한다.

RAID 0+1 / 1+0 △: 스트라이핑과 미러링을 조합한 Nested RAID. 성능과 안정성을 모두 추구하지만 디스크 소요량이 크다.

🔥 TLC가 SLC·MLC보다 용량은 크지만 속도가 느린 이유

한 셀에 저장하는 비트 수가 늘어날수록, 그 셀이 가질 수 있는 전압(전하량) 레벨의 개수가 지수적으로 늘어난다(1비트=2단계, 2비트=4단계, 3비트=8단계). 읽기/쓰기를 할 때 컨트롤러는 더 촘촘하고 많은 전압 구간을 정밀하게 구분해야 하므로, 한 번에 판별·기록하는 데 더 많은 시간과 정밀한 제어가 필요하다. 또한 전압 구간 간격이 좁아지면서 셀 간 간섭(오류) 가능성도 커져, 오류 정정(ECC) 처리 부담도 증가한다. 이것이 속도 저하와 셀 수명 단축(잦은 재기록으로 인한 마모)의 근본 원인이다.

SSD의 FTL (Flash Translation Layer) 🔥

필요성: SSD는 블록(Block)/페이지(Page) 단위로 동작하지만, 운영체제는 섹터(Sector) 기반으로 저장장치를 인식한다. 이 간극을 메우기 위해 컨트롤러가 논리 섹터 주소 ↔ 물리 블록/페이지 주소를 매핑해 준다.

플래시 메모리의 근본 제약 (FTL이 필요한 이유의 뿌리) - 덮어쓰기(Overwrite) 불가: 데이터를 수정하려면 반드시 블록 전체를 먼저 지운(Erase) 뒤 다시 써야 함 - 읽기/쓰기는 페이지 단위, 삭제는 블록 단위(블록 하나에 여러 페이지 포함) — 단위 불일치 - 블록별 삭제 횟수(P/E Cycle)에 물리적 수명 한계가 있음

🔥 Wear Leveling (웨어 레벨링) - 정의: 특정 블록에만 쓰기/삭제가 몰리지 않도록, 모든 블록에 걸쳐 삭제 횟수를 고르게 분산시키는 기법 - 필요 이유: 플래시 셀은 삭제 횟수 제한이 있다. 자주 쓰는 블록만 계속 쓰면 그 블록만 먼저 마모되어 SSD 전체 수명이 실제보다 훨씬 짧아진다 - 방식: 새로 쓸 데이터는 삭제 횟수가 적은 블록에 우선 배치(Dynamic), 거의 안 바뀌는(Cold) 데이터도 주기적으로 이동시켜 그 블록도 마모에 동참시킴(Static)

🔥 Garbage Collection (가비지 컬렉션) - 정의: 수정되어 더 이상 유효하지 않은(Invalid) 페이지들을 정리하여 쓰기 가능한 빈 블록을 확보하는 기법 - 필요 이유: 덮어쓰기가 불가능하므로, 데이터 수정 시 기존 페이지는 무효화하고 새 페이지에 새로 쓴다(Out-of-place update). 이 무효 페이지들이 계속 쌓이면 빈 공간이 고갈된다 - 동작: 유효 데이터와 무효 데이터가 섞인 블록에서 유효한 페이지만 다른 블록으로 복사한 뒤, 원래 블록 전체를 삭제(Erase) 하여 재사용 가능하게 만듦 - 부작용: 유효 페이지를 복사하는 과정에서 추가 쓰기가 발생(Write Amplification, 쓰기 증폭) → SSD 성능 저하 및 수명 단축의 원인이 되기도 함

Wear Leveling과 Garbage Collection의 관계: GC가 블록을 지우고 재사용 가능하게 만드는 과정에서, Wear Leveling은 "어느 블록을 재사용 대상으로 고를지"에 마모도 균형이라는 기준을 추가로 반영한다. 둘은 상호 보완적으로 동작한다.

플래시 메모리 3대 성질 — 여기서 FTL·웨어 레벨링·GC가 나온다 🔥

# 성질 결과
① 읽기·쓰기 = 페이지 단위, 지우기 = 블록(여러 페이지) 단위 지울 땐 블록 통째로 → 가비지 컬렉션 필요
② 덮어쓰기 불가(Erase-before-Write) 수정은 새 페이지에 쓰고 옛 페이지는 무효 → FTL 매핑 필요
③ 블록당 지우기 횟수(P/E 사이클) 제한 많이 지운 블록부터 고장 → 웨어 레벨링 필요

🔥 딥러닝 연산에 GPU가 유리한 이유

딥러닝의 핵심 연산인 행렬 곱셈·합성곱(Convolution) 은, 동일한 단순 연산(곱셈+덧셈)을 수백만 개의 서로 다른 데이터에 대해 독립적으로, 동시에 반복하는 구조다. (= 데이터 병렬성이 매우 높음)

CPU는 소수의 강력한 코어로 복잡한 분기 처리를 빠르게 하는 데 최적화되어 있어, 이런 단순 반복 연산을 코어 개수만큼만 나눠 순차적으로 처리한다.

반면 GPU는 제어 로직을 최소화하는 대신 그 면적에 수천 개의 단순 ALU를 배치한 구조이므로, 행렬의 각 원소 연산을 수천 개의 스레드가 동시에(병렬로) 수행할 수 있다. 이 대규모 병렬 처리 능력이 CPU 대비 압도적인 학습·추론 속도 향상을 가져온다.

정리하면: 딥러닝 연산 = 단순 연산의 대량 반복(데이터 병렬성) → GPU의 구조(다수의 단순 ALU)와 정확히 부합하기 때문이다.

명령어 형식

명령어 = 연산 코드(Opcode) + 오퍼랜드(주소). 연산 코드가 n 비트면 최대 2ⁿ 가지 명령을 표현한다.

형식예 (X = A + B)특징
0-주소PUSH A; PUSH B; ADD; POP X스택 구조. 명령어 짧음

3-주소ADD X, A, B프로그램 짧음, 명령어 김

예제. 명령어의 주소 필드가 500, PC = 200(다음 명령어 주소), 인덱스 레지스터 = 100, M[500] = 800 일 때 각 방식의 유효 주소는?

풀이
  • 직접: 500
  • 간접: M[500] = 800
  • 상대: PC + 500 = 700
  • 인덱스: 100 + 500 = 600
  • 즉시: 유효 주소 없음 (오퍼랜드 500 이 곧 값)

풀이
  • 평균 CPI = 0.5×1 + 0.3×2 + 0.2×3 = 1.7
  • CPU 시간 = 10⁹ × 1.7 / (2×10⁹) = 0.85초
  • MIPS = 클록 주파수 / (CPI × 10⁶) = 2×10⁹ / (1.7×10⁶) ≈ 1176 MIPS

암달의 법칙 (Amdahl's Law)

전체 속도 향상 = 1 / ((1 − P) + P / S)
P = 개선되는 부분의 비율, S = 그 부분의 속도 향상 배수

예제. 프로그램의 80% 가 병렬화 가능하다. 코어 4개일 때와 코어가 무한할 때의 속도 향상은?

풀이
  • 4코어: 1 / (0.2 + 0.8/4) = 1 / 0.4 = 2.5배
  • 무한: 1 / 0.2 = 5배 (상한)

결론: 개선할 수 없는 부분(순차 구간)이 전체 성능의 상한을 정한다. 그래서 "자주 실행되는 부분을 빠르게 하라(Make the common case fast)". 서버를 아무리 늘려도 DB 락 같은 직렬 구간이 남으면 처리량은 한계에 닿는다.

캐시 일관성과 거짓 공유

코어마다 캐시가 따로 있으므로, 한 코어가 값을 바꾸면 다른 코어의 사본을 무효화해야 한다(MESI 프로토콜: Modified · Exclusive · Shared · Invalid).

  • 거짓 공유(False Sharing): 서로 다른 변수인데 같은 캐시 라인(보통 64바이트) 에 놓여, 두 스레드가 각자 자기 변수만 써도 캐시 라인이 계속 무효화되어 느려지는 현상. → 변수 사이에 패딩을 넣어 다른 캐시 라인에 둔다.
  • 가시성 문제: 한 스레드가 바꾼 값이 다른 스레드에 바로 보이지 않을 수 있다(레지스터·캐시·명령어 재배치). Java 의 volatile 은 항상 최신 값을 읽도록 보장하지만 원자성은 보장하지 않는다.

4-14. 부동소수점 · 엔디안 ⭐ 🧮

IEEE 754 단정도 (32비트)

│ 부호 1비트 │ 지수 8비트 (바이어스 127) │ 가수 23비트 │
값 = (−1)^부호 × 1.가수 × 2^(지수 − 127)
형식부호지수가수바이어스유효 숫자
단정도 (float)1823127약 7자리
배정도 (double)111521023약 15~16자리

예제. −6.75 를 IEEE 754 단정도로 표현하라.

풀이
  1. 부호: 음수 → 1
  2. 2진수 변환: 6.75 = 110.11₂
  3. 정규화: 1.1011 × 2² (소수점 앞이 1 이 되게 이동)
  4. 지수: 2 + 127 = 129 = 10000001
  5. 가수: 정규화한 수의 소수점 아래 1011 뒤를 0 으로 채움 → 10110000000000000000000
  6. 결과: 1 10000001 10110000000000000000000 = 0xC0D80000

맨 앞의 1 은 항상 1 이므로 저장하지 않는다(숨은 비트). 그만큼 1비트의 정밀도를 더 얻는다.

특수 값지수가수
±0모두 00
비정규 수 (0 에 가까운 수)모두 00 아님
±무한대모두 10
NaN모두 10 아님
  • 0.1 + 0.2 ≠ 0.3: 0.1 은 2진수로 무한 소수(0.000110011…)라 정확히 표현되지 않는다. → 실수 비교는 |a − b| < ε 로, 금액 계산은 정수(최소 화폐 단위)나 십진 타입(BigDecimal, DECIMAL) 으로 한다.
  • 큰 수와 아주 작은 수를 더하면 작은 수가 사라진다(정밀도 손실). 덧셈의 결합 법칙이 성립하지 않는다.
  • NaN == NaN 은 거짓이다.

엔디안 (Endianness)

여러 바이트로 된 값을 메모리에 놓는 순서. 0x12345678 을 주소 100 부터 저장하면:

주소100101102103
빅 엔디안12345678
리틀 엔디안78563412
  • 빅 엔디안: 상위 바이트부터. 사람이 읽는 순서. 네트워크 바이트 순서.
  • 리틀 엔디안: 하위 바이트부터. x86, 대부분의 ARM 구성.
  • 서로 다른 시스템이 이진 데이터를 주고받을 때 변환이 필요하다(htonl, ntohl). JSON 같은 텍스트 형식은 이 문제가 없다.
