자료구조 문제의 답은 대부분 "어떤 연산이 자주 일어나는가" 에서 나온다. 조회가 많은가, 삽입·삭제가 많은가, 순서가 필요한가, 범위 검색이 필요한가를 먼저 묻는다.

동적 배열과 분할 상환 분석

가득 차면 2배 크기의 새 배열을 잡고 전부 복사한다.

  • 복사는 O(n) 이지만 n 번 삽입하는 동안 복사 횟수의 합은 1 + 2 + 4 + … + n < 2n 이다.
  • 따라서 삽입 한 번의 분할 상환(amortized) 비용은 O(1).
  • 크기를 2배가 아니라 일정량씩 늘리면 n 번 삽입에 O(n²) 이 든다.
  • 재할당 순간 한 번의 지연이 문제인 실시간 시스템에서는 용량을 미리 예약한다.

연결 리스트 종류와 단골 문제

종류특징
단일 연결다음 노드만 가리킴. 이전 노드로 못 감
이중 연결앞뒤를 모두 가리킴. 노드가 주어지면 O(1) 삭제
원형 연결마지막이 처음을 가리킴. 라운드 로빈
문제풀이
뒤집기prev, cur, next 세 포인터로 방향을 하나씩 바꿈
가운데 노드느린 포인터 1칸, 빠른 포인터 2칸
사이클 검출플로이드의 토끼와 거북이 — 두 포인터가 만나면 사이클
뒤에서 k 번째한 포인터를 k 칸 먼저 보낸 뒤 함께 이동
정렬된 두 리스트 병합더미 헤드를 두고 작은 쪽을 이어 붙임
ListNode reverse(ListNode head) {
    ListNode prev = null, cur = head;
    while (cur != null) {
        ListNode next = cur.next;
        cur.next = prev;
        prev = cur;
        cur = next;
    }
    return prev;
}

원형 큐

배열로 큐를 만들면 앞에서 꺼낸 자리가 낭비된다. → 인덱스를 나머지 연산으로 순환시킨다.

  • 삽입: rear = (rear + 1) % N / 삭제: front = (front + 1) % N
  • 공백: front == rear / 포화: (rear + 1) % N == front
  • 공백과 포화를 구분하려고 한 칸을 비워 둔다 → 크기 N 인 배열에 최대 N−1 개 저장.

후위 표기법

예제. 중위식 A + B * (C − D) / E 를 후위식으로 바꾸고, 후위식 5 3 2 * + 4 − 를 계산하라.

풀이

중위 → 후위 (연산자 스택 사용)

  1. 피연산자는 바로 출력한다.
  2. 연산자는 스택 꼭대기의 연산자가 자신보다 우선순위가 높거나 같으면 꺼내 출력한 뒤 자신을 넣는다.
  3. ( 는 무조건 넣고, ) 를 만나면 ( 가 나올 때까지 꺼내 출력한다.

결과: A B C D − * E / +

후위식 계산 (피연산자 스택 사용)

읽은 것동작스택
5, 3, 2넣는다5 3 2
*3 × 2 = 65 6
+5 + 6 = 1111
4넣는다11 4
−11 − 4 = 77

연산자를 만나면 먼저 꺼낸 값이 오른쪽 피연산자다 (11 − 4 이지 4 − 11 이 아니다).

서로를 구현하기

  • 스택 2개로 큐: 넣을 때는 in 스택에, 꺼낼 때는 out 스택이 비었으면 in 을 전부 옮긴 뒤 out 에서 꺼낸다. 원소마다 최대 두 번 이동하므로 분할 상환 O(1).
  • 최솟값을 O(1) 에 주는 스택: 값과 함께 "그 시점까지의 최솟값"을 같이 쌓는다.

키를 해시 함수로 배열 인덱스로 바꿔 평균 O(1) 에 삽입·조회·삭제한다.

부하율과 재해싱

부하율 α = 저장된 원소 수 / 버킷 수. α 가 임계값을 넘으면 버킷을 2배로 늘리고 모든 원소를 다시 배치(rehash)한다.

  • Java HashMap: 기본 용량 16, 부하율 0.75. 한 버킷의 리스트가 8개를 넘으면 레드-블랙 트리로 바꿔 최악 O(n) 을 O(log n) 으로 줄인다.
  • 최악의 경우(모든 키가 한 버킷) O(n). 해시 함수를 아는 공격자가 충돌 키를 대량으로 보내는 해시 충돌 DoS 가 가능하다 → 실행마다 다른 시드를 쓰는 해시로 방어.

6-4. 트리 · 이진 탐색 트리 🔥 ✍️

용어

용어뜻
차수 (Degree)한 노드의 자식 수. 트리의 차수는 그 최댓값

이진 탐색 트리 (BST)

왼쪽 서브트리의 모든 키 < 노드의 키 < 오른쪽 서브트리의 모든 키

연산평균최악 (편향)
탐색·삽입·삭제O(log n)O(n)

삭제의 세 경우

  1. 잎 노드 → 그냥 제거
  2. 자식 1개 → 자식을 그 자리로 올림
  3. 자식 2개 → 중위 후속자(오른쪽 서브트리의 최솟값) 또는 중위 선행자(왼쪽 서브트리의 최댓값)를 그 자리에 복사하고, 그 후속자를 삭제
  • 정렬된 순서(1, 2, 3, 4…)로 삽입하면 한쪽으로만 뻗어 연결 리스트와 같아진다. → 균형 트리가 필요한 이유.

6-5. 균형 트리 — AVL · Red-Black · B/B+ ⭐

AVL 트리

모든 노드에서 왼쪽·오른쪽 서브트리의 높이 차이가 1 이하. 깨지면 회전으로 복구한다.

레드-블랙 트리

  1. 모든 노드는 빨강 또는 검정
  2. 루트는 검정
  3. 모든 잎(NIL)은 검정
  4. 빨강 노드의 자식은 모두 검정 (빨강이 연속될 수 없음)
  5. 어떤 노드에서 그 아래 잎까지 가는 모든 경로의 검정 노드 수가 같다

→ 가장 긴 경로가 가장 짧은 경로의 2배를 넘지 않는다.

B 트리 · B+ 트리

디스크는 블록 단위로 읽고, 한 번의 접근이 메모리보다 매우 느리다. → 한 노드에 키를 많이 담아 트리 높이를 낮춘다.

차수 m 인 B 트리: 노드당 자식 최대 m 개, 키 최대 m−1 개, 루트를 뺀 노드는 자식 최소 ⌈m/2⌉ 개, 모든 잎이 같은 깊이.

구분B 트리B+ 트리
데이터 위치모든 노드잎 노드에만 (내부 노드는 키만)
잎 노드 연결없음연결 리스트로 연결
범위 검색트리를 오르내려야 함잎을 따라 순차 스캔
내부 노드의 분기 수적음 (데이터도 담으므로)많음 → 트리가 더 낮음
탐색 시간위쪽에서 일찍 끝날 수 있음항상 잎까지 (일정)

예제. 노드 하나에 키가 100개 들어가는 B+ 트리의 높이가 3 일 때 색인할 수 있는 레코드 수는 대략 얼마인가?

풀이

분기 수가 약 100 이므로 100 × 100 × 100 = 약 100만 건. 높이 4 면 약 1억 건. 수억 건의 테이블도 디스크를 3~4번만 읽으면 원하는 행에 닿는다. 상위 노드는 대부분 메모리에 캐시되어 있으므로 실제 디스크 접근은 더 적다.

  • B 트리의 삽입·분할 과정은 → B-Tree 삽입 · 분할

6-6. 힙 · 우선순위 큐 🔥 ✍️

완전 이진 트리 + 부모가 자식보다 항상 크다(최대 힙) / 작다(최소 힙). 형제 사이에는 순서가 없다.

배열 표현

완전 이진 트리이므로 빈칸 없이 배열에 담는다. 인덱스가 0 부터일 때:

  • 부모: (i − 1) / 2, 왼쪽 자식: 2i + 1, 오른쪽 자식: 2i + 2
  • (인덱스가 1 부터면 부모 i / 2, 자식 2i, 2i + 1)
연산방법시간
삽입맨 끝에 넣고 부모와 비교하며 위로 (sift-up)O(log n)
최댓값/최솟값 삭제루트를 꺼내고 마지막 원소를 루트로 옮긴 뒤 아래로 (sift-down)O(log n)
최댓값/최솟값 조회루트O(1)
배열 → 힙 구성마지막 내부 노드부터 거꾸로 sift-downO(n)
임의 값 탐색순서가 약해 전체 탐색O(n)

예제. 최대 힙 [90, 70, 80, 30, 60, 50] 에 85 를 삽입한 뒤, 최댓값을 삭제한 결과는?

풀이

삽입: 끝에 85 → [90, 70, 80, 30, 60, 50, 85]. 85(인덱스 6)의 부모는 인덱스 2 의 80 → 교환 → [90, 70, 85, 30, 60, 50, 80]. 부모 90 > 85 이므로 멈춤.

삭제: 루트 90 을 꺼내고 마지막 원소 80 을 루트로 → [80, 70, 85, 30, 60, 50]. 자식 70, 85 중 큰 85 와 교환 → [85, 70, 80, 30, 60, 50]. 80 의 자식은 50 뿐이고 80 > 50 이므로 멈춤.

결과: [85, 70, 80, 30, 60, 50]

  • 힙 구성이 O(n) 인 이유: 아래쪽 노드일수록 수는 많지만 내려갈 거리가 짧다. 높이 h 인 노드가 n/2^(h+1) 개이고 각각 h 만큼만 내려가므로 합이 O(n) 이다.
  • 힙 정렬: 힙 구성 O(n) + 최댓값 삭제 n 번 O(n log n). 제자리 정렬, 불안정 정렬.

6-8. 트라이 · 블룸 필터 · LRU 캐시 ⭐

트라이 (Trie)

문자열을 한 글자씩 간선으로 저장하는 트리. 공통 접두사를 공유한다.

          (root)
         /      \
        c        d
        |        |
        a        o
       / \       |
      t   r      g*
      *   *
  • 길이 M 인 문자열의 삽입·검색이 O(M) — 저장된 문자열 수와 무관.
  • 용도: 자동 완성, 사전, 접두사 검색, IP 라우팅 테이블의 최장 접두사 일치.
  • 단점: 노드마다 자식 포인터 배열을 두면 메모리를 많이 쓴다.

블룸 필터 (Bloom Filter)

원소가 집합에 있는지를 아주 적은 메모리로 판정하는 확률적 자료구조. 비트 배열 하나와 해시 함수 k 개를 쓴다.

  • 삽입: k 개 해시 위치의 비트를 1 로 설정.
  • 조회: k 개 위치가 모두 1 이면 "있을 수도 있다", 하나라도 0 이면 "확실히 없다".
성질내용
거짓 양성있음 (없는데 있다고 답할 수 있음)
거짓 음성없음 (있는데 없다고 답하지 않음)
삭제불가 (계수 블룸 필터로 보완)
  • 용도: DB·캐시에 없는 키를 조회하러 가는 비용을 미리 차단(LSM 트리의 SSTable, 캐시 관통 방지), 중복 URL 검사.

LRU 캐시 구현

"가장 오래 쓰지 않은 것을 버린다"를 조회·삽입 모두 O(1) 로 구현하라는 단골 문제.

해시 맵 + 이중 연결 리스트

  • 해시 맵: 키 → 리스트 노드 (O(1) 조회)
  • 이중 연결 리스트: 사용 순서 유지. 접근하면 노드를 맨 앞으로 옮기고, 용량을 넘으면 맨 뒤를 제거 (O(1))
class LRUCache<K, V> extends LinkedHashMap<K, V> {
    private final int capacity;

    LRUCache(int capacity) {
        super(16, 0.75f, true);        // accessOrder = true
        this.capacity = capacity;
    }

    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        return size() > capacity;
    }
}
