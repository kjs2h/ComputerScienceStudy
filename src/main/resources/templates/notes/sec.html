🔥 비대칭키를 이용한 대칭키 교환 순서

배경: 비대칭키는 안전하지만 느리다. 대칭키는 빠르지만 키를 어떻게 안전하게 전달하느냐가 문제다. → 해결: 느린 비대칭키로 "대칭키 자체"만 한 번 안전하게 전달하고, 이후 실제 데이터는 빠른 대칭키로 주고받는다. 이것이 하이브리드 암호 방식이고 TLS의 원리다.

교환 순서 (서버 A ← 클라이언트 B)

① 서버 A가 공개키/개인키 쌍을 생성한다.
   (개인키는 절대 외부로 내보내지 않고 안전하게 보관)

② 클라이언트 B가 서버 A에 접속을 요청한다.

③ 서버 A는 자신의 공개키가 담긴 인증서(CA가 서명)를 B에게 전송한다.

④ B는 CA의 공개키로 인증서 서명을 검증하여
   "이 공개키가 정말 A의 것인지" 확인한다.  ← 중간자 공격(MITM) 방지 단계

⑤ B가 세션에서 사용할 대칭키(세션 키)를 생성한다.

⑥ B는 이 대칭키를 A의 공개키로 암호화하여 A에게 전송한다.

⑦ A는 자신의 개인키로 복호화하여 대칭키를 획득한다.
   → 개인키는 A만 가지고 있으므로, 도중에 가로채도 복호화 불가능

⑧ 이후 A와 B는 이 공유된 대칭키로 실제 데이터를 암호화하여 통신한다.

④번 인증서 검증 단계를 빼먹지 말 것. 이게 없으면 공격자가 자기 공개키를 A의 것인 척 보내는 중간자 공격이 성립한다. 이 단계를 쓰면 확실한 가점 요소다.

VPN · IPSec ⭐

VPN (Virtual Private Network, 가상 사설망): 인터넷 같은 공용망 위에 암호화된 터널을 만들어 전용선처럼 안전하게 통신하는 기술 (터널링 + 암호화 + 인증).

  • 원리 — 터널링: 원본 패킷을 통째로 암호화해 새 패킷 안에 캡슐화해 보낸다.
  • 필요성: 전용선은 비싸다. 인터넷을 쓰면서 암호화로 보안을 확보해 저비용으로 사설망 수준의 보안을 얻는다.
유형 용도
Site-to-Site 본사 ↔ 지사 네트워크 연결
Remote Access 재택·출장자가 회사망에 접속
계층별 IPSec(3계층), SSL/TLS VPN(응용), L2TP(2계층)

IPSec (IP Security): IP 계층(3계층)에서 패킷을 인증·암호화하는 프로토콜 모음, VPN 구현의 표준. (방화벽이 아님 — 방화벽은 차단, IPSec은 암호화)

구성 역할
AH (Authentication Header) 인증 + 무결성 (암호화 X)
ESP (Encapsulating Security Payload) 인증 + 무결성 + 암호화(기밀성)
IKE (Internet Key Exchange) 키 교환, SA(보안 연관) 설정
모드 보호 범위 용도
전송 모드 IP 페이로드만, 원래 IP 헤더 유지 호스트 ↔ 호스트
터널 모드 원래 IP 패킷 전체를 암호화하고 새 IP 헤더를 붙임 게이트웨이 ↔ 게이트웨이 (VPN)
  • 3계층에서 동작하는 이점: 상위 계층(TCP/UDP, 응용) 프로그램을 고치지 않고도 모든 트래픽에 보안을 적용할 수 있다.

🔥 DoS vs DDoS

DoS (Denial of Service) DDoS (Distributed DoS)
정의 단일 공격자가 대상 시스템의 자원을 고갈시켜 정상 서비스를 불가능하게 만드는 공격 다수의 분산된 좀비 PC(봇넷) 를 동원한 DoS 공격
공격 출발지 하나 또는 소수 수천~수십만 개
차단 난이도 상대적으로 쉬움 (IP 차단) 매우 어려움 — 출발지가 정상 사용자와 구별되지 않음
구조 공격자 → 대상 공격자 → C&C 서버 → 좀비 PC 다수 → 대상
공격 유형 SYN Flooding, Ping of Death, Teardrop, Land Attack, Slowloris UDP Flooding, DNS/NTP 증폭(Amplification) 공격, HTTP Flooding

대응 방안: 방화벽/IPS, 트래픽 임계치 기반 필터링, CDN 및 트래픽 분산, Anycast, 클라우드 DDoS 방어 서비스(스크러빙 센터), Rate Limiting, 좀비 PC 감염 예방

🔥 SYN Flooding

공격 방식

1. 공격자가 서버로 SYN 패킷을 대량 전송한다.
   이때 출발지 IP를 존재하지 않는 주소로 위조(IP Spoofing)한다.

2. 서버는 각 SYN에 대해 SYN+ACK를 보내고,
   연결 정보를 백로그 큐(Backlog Queue)에 저장한 뒤
   SYN_RECEIVED 상태로 마지막 ACK를 기다린다.

3. 출발지가 위조되었으므로 ACK는 영원히 오지 않는다.
   → 연결이 half-open 상태로 큐를 점유한 채 방치된다.

4. 백로그 큐가 가득 차면
   → 정상 사용자의 연결 요청조차 거부된다. (서비스 거부)

핵심: 3-way Handshake의 미완성 상태를 악용하여 서버의 연결 큐(자원)를 고갈시키는 공격. 대역폭이 아니라 상태 정보 자원을 고갈시킨다는 점이 특징이다.

해결 방법

방법 설명
① SYN Cookie 서버가 백로그 큐에 상태를 저장하지 않고, 연결 정보를 해시한 값을 SYN+ACK의 시퀀스 번호에 담아 보낸다. 클라이언트가 ACK로 그 값을 되돌려 주면 그때 비로소 연결을 생성한다. → 상태를 저장하지 않으므로 큐가 고갈되지 않는다. 가장 근본적인 대응
② 백로그 큐 크기 증가 임시방편. 근본 해결은 아님
③ SYN_RECEIVED 타임아웃 단축 half-open 연결을 빨리 정리
④ 방화벽/IPS 필터링 동일 출발지의 비정상적 SYN 폭주 차단, Rate Limiting
⑤ First SYN Drop 첫 SYN을 의도적으로 버리고 재전송되는지 확인 (정상 클라이언트만 재전송함)
⑥ 침입 차단 시스템 위조된 출발지 IP 필터링(Ingress Filtering)

🔥 ARP Spoofing

공격이 가능한 근본 원인

ARP 프로토콜은 ARP Reply를 받았을 때 그것이 진짜인지 검증하는 인증 절차가 전혀 없다. 요청하지 않은 응답(Gratuitous ARP)도 그대로 받아들여 캐시 테이블을 갱신한다.

공격 방식

1. 공격자가 피해자 PC에게 위조된 ARP Reply를 반복 전송한다.
   "게이트웨이(192.168.1.254)의 MAC은 나(공격자 MAC)야"

2. 동시에 게이트웨이에게도 위조 ARP Reply를 보낸다.
   "피해자(192.168.1.x)의 MAC은 나야"

3. 양쪽의 ARP 캐시 테이블이 오염된다.

4. 이제 피해자 ↔ 게이트웨이 사이의 모든 트래픽이
   공격자를 경유하게 된다.
   → 중간자 공격(MITM) 성립

5. 공격자는 트래픽을 도청(스니핑)하거나 변조한 뒤,
   다시 정상 목적지로 전달(포워딩)한다.

🔥 시나리오 — 공격자 판별하기

주어진 상황(게이트웨이 = 192.168.1.254, MAC: X):

PC IP 실제 MAC
PC A 192.168.1.1 A
PC B 192.168.1.2 B
PC C 192.168.1.3 C
라우터 192.168.1.254 X

각 PC의 ARP 캐시 테이블:

PC A의 테이블 PC B의 테이블 PC C의 테이블
192.168.1.2 → B 192.168.1.1 → A 192.168.1.1 → A
192.168.1.3 → C 192.168.1.3 → C 192.168.1.2 → B
192.168.1.254 → B ⚠️ 192.168.1.254 → X ✅ 192.168.1.254 → B ⚠️

판별 논리 (답안 구조)

① 게이트웨이(192.168.1.254)의 실제 MAC은 X 이다.
② 그런데 PC A와 PC C의 ARP 테이블에는
   192.168.1.254 → MAC B 로 잘못 기록되어 있다.
③ MAC B는 PC B의 MAC 주소이다.
④ 오직 PC B만이 게이트웨이의 MAC을 X(정상)로 올바르게 알고 있다.
   → 공격자는 자기 자신은 정상 경로를 유지해야
     가로챈 트래픽을 실제 게이트웨이로 포워딩할 수 있기 때문이다.

✅ 결론: 공격자 호스트는 PC B 이며,
   현재 진행 중인 공격은 ARP Spoofing을 이용한
   중간자 공격(MITM)이다.

판별 핵심: "자기 테이블만 정상이고 남들 테이블만 오염된 PC"가 공격자다. 이 논리를 답안에 반드시 명시할 것.

🔥 공격 성공 후에도 은닉이 가능했던 이유 1. 트래픽을 그대로 포워딩하기 때문이다. 공격자는 가로챈 패킷을 도청·복사한 뒤 정상 목적지로 다시 전달하므로, 피해자 입장에서는 인터넷이 정상 동작하는 것처럼 보여 이상을 감지할 수 없다. 2. ARP는 2계층 프로토콜이라 로컬 네트워크 내부에서만 동작한다. 라우터를 넘어가지 않으므로 외부 보안 장비나 방화벽 로그에 흔적이 남지 않는다. 3. ARP 캐시는 주기적으로 만료되지만, 공격자가 위조 ARP Reply를 지속적으로 재전송하여 오염 상태를 유지한다. 4. ARP에는 인증·로깅 메커니즘이 없어 정상 갱신과 공격을 구별할 근거가 남지 않는다.

🔥 기술적 보안 대책

대책 설명
① 정적 ARP 테이블(Static ARP) 설정 게이트웨이 등 중요 장비의 IP-MAC 매핑을 수동으로 고정하여 ARP Reply로 갱신되지 않게 한다. 가장 확실하지만 관리 부담이 크다
② DAI (Dynamic ARP Inspection) 스위치가 DHCP Snooping 테이블과 대조하여 위조된 ARP 패킷을 차단한다
③ Port Security 스위치 포트별로 허용 MAC 주소를 제한
④ ARP 감시 도구 arpwatch 등으로 IP-MAC 매핑 변경을 실시간 탐지·경보
⑤ 네트워크 분할 VLAN으로 브로드캐스트 도메인을 분리하여 공격 범위를 축소
⑥ 종단 간 암호화 HTTPS, VPN, TLS 적용 — 가로채도 내용을 볼 수 없게 한다 (근본적 피해 완화)
⑦ 802.1X 인증 네트워크 접속 자체에 인증을 요구하여 미인가 장비 차단

사회공학 기법 (Social Engineering) ⭐

정의: 기술적 취약점이 아니라 사람의 심리·신뢰·부주의를 악용하여 기밀 정보를 획득하거나 시스템에 침투하는 공격 기법.

기법 설명
피싱(Phishing) 정상 기관을 사칭한 이메일/사이트로 계정 정보 탈취
스피어 피싱(Spear Phishing) 특정 인물·조직을 겨냥한 맞춤형 피싱 (실명, 직책, 업무 내용 활용)
스미싱(Smishing) 문자메시지(SMS)로 악성 링크 유도
보이스 피싱(Vishing) 전화 통화로 금융/개인 정보 요구
파밍(Pharming) DNS 변조 등으로 정상 주소를 입력해도 가짜 사이트로 유도
테일게이팅(Tailgating)/피기배킹 출입 인가자를 뒤따라 물리적으로 무단 진입
숄더 서핑(Shoulder Surfing) 어깨너머로 비밀번호 훔쳐보기
덤스터 다이빙(Dumpster Diving) 폐기된 문서·저장매체에서 정보 수집
프리텍스팅(Pretexting) 그럴듯한 상황을 꾸며(IT 지원팀 사칭 등) 정보를 요구
미끼(Baiting) 악성코드가 담긴 USB를 흘려두어 꽂게 유도

대응: 정기적 보안 인식 교육, 모의 훈련, 다중 인증(MFA), 정보 요청 시 별도 채널로 신원 재확인 절차 마련, 문서 파쇄 정책

DoS 정의 서술 틀 🔥

DoS: 대상 시스템의 자원(CPU·메모리·대역폭·연결 큐)을 고갈시켜 정상 사용자가 서비스를 이용하지 못하게 하는 공격 — 정보보안 3요소 중 가용성(Availability) 침해. DDoS: 악성코드에 감염된 다수의 좀비 PC(봇넷)를 C&C 서버로 조종해 동시에 DoS를 수행 — 출발지가 많고 정상 트래픽과 구별이 어려워 차단이 어렵다.

Ping of Death 🔥

  • 원리: ICMP Echo Request를 IP 최대 크기(65,535바이트)보다 크게 만들어 전송 → 전송 중 단편화(Fragmentation) → 수신 측이 재조합할 때 버퍼가 넘쳐(Overflow) 시스템이 다운
  • 대응: 비정상 크기·단편화된 ICMP 패킷 차단, OS 패치(재조합 전 길이 검사), 방화벽에서 ICMP 제한
  • 같은 계열(단편화 악용): Teardrop(단편 offset을 겹치게 조작), Land Attack(출발지 IP = 목적지 IP)
공격 핵심 동작 고갈되는 자원
Ping of Death 핑을 크게 재조합 버퍼(메모리)
ICMP Flooding / Smurf 핑을 많이 (Smurf는 브로드캐스트 증폭) 대역폭
SYN Flooding 연결을 반쯤만 열어 둠 백로그 큐(연결 상태 정보)

⚠️ 실제 오답 사례: "쓸데없는 핑을 많이 보내 대기 큐를 채운다"는 Ping of Death가 아니다. "많이"는 ICMP Flooding, "큐 고갈"은 SYN Flooding이다. 고갈 자원으로 구별한다.

IP Spoofing — TCP 신뢰 관계 악용 공격 🔥 ✍️

목적: Target이 "이 IP는 믿을 수 있다"고 설정해 둔 IP 기반 신뢰 관계(rlogin/rsh, .rhosts)를 이용해 인증 없이 접속하는 것.

공격자 ──① DoS(SYN Flooding)──────────▶ 정상 사용자 (응답 불능)
공격자 ──② SYN (출발지 = 정상 사용자 IP)─▶ Target
Target ──③ SYN/ACK ──────────────────▶ 정상 사용자 (무력화되어 RST 못 보냄)
공격자 ──④ ACK (ACK = 예측한 ISN + 1) ──▶ Target
         ⑤ 연결 완료 → Target은 신뢰 호스트로 착각, 명령 실행 허용
단계 설명 (답안에 꼭 들어갈 키워드)
① 정상 사용자를 DoS로 무력화 — ③의 SYN/ACK를 받으면 "요청한 적 없다"며 RST로 연결을 끊어버리기 때문
② 출발지 IP를 정상 사용자로 위조한 SYN 전송 (이것이 Spoofing)
④ 공격자는 SYN/ACK를 보지 못한다(정상 사용자에게 감) → Target의 ISN(초기 순서 번호)을 예측해 ACK = ISN + 1 전송 → "Blind Spoofing"

ISN 예측 원리: 과거 OS는 ISN을 규칙적 카운터로 생성(예: 초기 BSD 계열 초당 +128,000, 연결당 +64,000). 공격자가 자기 IP로 정상 연결을 여러 번 맺어 ISN을 관찰 → 증가 규칙 파악 → 다음 ISN 추정 (1994 미트닉 사건).

  • 취약점 원인 2가지: ① IP 주소만으로 인증하는 신뢰 관계 ② 예측 가능한 ISN
  • 대응: ISN 무작위화(RFC 6528: ISN = 타이머 + Hash(4-tuple, 비밀키)), IP 기반 인증(rhosts) 폐지 → SSH 등 암호 인증, 외부에서 들어오는 내부 IP 패킷 차단(Ingress Filtering)

DRDoS (Distributed Reflection DoS) 🔥

Reflection = 반사. 피해자를 직접 공격하지 않고 정상 서버들을 거울처럼 이용한다.

공격자 ── 요청(출발지 IP = 피해자 IP로 위조) ──▶ 정상 서버 다수 (DNS, NTP 등 = 반사체)
                                                   │ 정상적으로 응답할 뿐인데
                                                   ▼ 응답이 전부 "출발지"로
                                                피해자 (트래픽 폭주)
  • 증폭(Amplification): 작은 요청으로 큰 응답을 얻는 서비스 이용 (DNS ANY 질의, NTP monlist, Memcached) — 주로 UDP 기반(연결 과정이 없어 위조 쉬움)
  • DDoS와 차이: 좀비 PC 없이도 가능, 공격 패킷의 출발지가 정상 서버라 추적·차단 어려움
  • 대응: 출발지 IP 위조 차단(Ingress Filtering, BCP 38), 반사체 서버의 불필요 서비스 비활성화(외부 재귀 DNS 차단, monlist 비활성화), 응답 빈도 제한(RRL·Rate Limiting), DDoS 방어 서비스
비교 DoS DDoS DRDoS
공격 주체 단일 공격자 봇넷(좀비 PC) 공격자 + 정상 서버(반사체)
패킷 출발지 공격자 좀비 PC 정상 서버
증폭 없음 수량으로 압도 응답 크기 증폭
추적 난이도 쉬움 어려움 매우 어려움

FTP 보안 — 능동/수동 모드, SFTP vs FTPS 🔥

FTP 구조: 제어 채널(TCP 21, 명령) + 데이터 채널(파일 전송) 2개 연결을 쓴다. 기본은 평문 전송이라 USER/PASS가 그대로 노출된다(스니핑).

명령어 의미
USER / PASS 사용자 ID / 비밀번호 전송 (평문)
PORT 능동 모드 — 클라이언트가 자기 데이터 포트를 서버에 알림
PASV 수동 모드 전환 요청 — 서버가 데이터 포트를 알려줌
RETR / STOR 파일 다운로드 / 업로드
FTPS (FTP over SSL/TLS) SFTP (SSH File Transfer Protocol)
기반 기존 FTP + TLS 암호화 SSH(22) 위의 별개 프로토콜
연결 제어·데이터 2채널 그대로 단일 연결
인증 X.509 인증서 + ID/PW SSH 키 또는 ID/PW
방화벽 데이터 포트 개방 필요 → 설정 복잡 22번 하나만 열면 됨

⚠️ 함정: SFTP는 "Secure FTP"가 아니라 SSH 기반의 전혀 다른 프로토콜이다.

능동(Active) 모드 vs 수동(Passive) 모드

[능동]  클라이언트 ──PORT 5001──▶ 서버:21      [수동]  클라이언트 ──PASV──▶ 서버:21
        클라이언트:5001 ◀──접속── 서버:20              클라이언트 ◀── "포트 50000" ── 서버
        (서버가 클라이언트로 연결)                     클라이언트 ──접속──▶ 서버:50000
  • 능동 모드 취약점 1. 서버가 클라이언트 쪽으로 접속하므로 클라이언트 방화벽이 외부발 인바운드 연결을 허용해야 함 → 클라이언트가 공격에 노출, NAT 환경에서는 연결 실패 2. FTP Bounce 공격: PORT 명령에 제3 호스트의 IP·포트를 넣어 서버가 그곳으로 접속하게 만듦 → 포트 스캔, 방화벽 우회
  • 해결 방안: 수동 모드 사용 + 서버의 수동 포트 범위를 좁게 제한, PORT 명령의 IP가 실제 클라이언트 IP와 같은지 검증(Bounce 차단), FTPS/SFTP로 암호화, 익명 FTP 비활성화

3-2. 암호 기초 — 해시 · MAC · 전자서명 · PKI 🔥

대칭키 vs 공개키 비교는 요약 → 대칭키 vs 비대칭키에 있다. 여기서는 그 위에 쌓는 내용만 다룬다.

목적 누구의 키로 암호화 누가 복호화
기밀성(나만 읽게) 받는 사람의 공개키 받는 사람의 개인키
전자서명(내가 보냈음을 증명) 보내는 사람의 개인키 누구나 보낸 사람의 공개키로 검증

해시 함수: 임의 길이 입력 → 고정 길이 출력, 일방향(역산 불가), 충돌 저항성. 예: SHA-256 (MD5·SHA-1은 취약). 용도: 비밀번호 저장(+솔트), 무결성 확인.

해시 MAC (HMAC) 전자서명
키 없음 공유 비밀키 개인키/공개키
보장 무결성(우연한 변경) 무결성 + 출처 인증 무결성 + 인증 + 부인 방지
  • 전자서명 절차: 메시지를 해시 → 해시값을 보낸 사람 개인키로 서명 → 수신자는 공개키로 서명을 풀어 직접 계산한 해시와 비교.
  • PKI: 공개키가 진짜 그 사람 것임을 CA(인증기관)가 인증서로 보증하는 체계. 인증서 = 공개키 + 소유자 정보 + CA의 전자서명. 폐지 확인: CRL, OCSP.
  • 정보보호 3요소(CIA): 기밀성 · 무결성 · 가용성 (+ 인증, 부인 방지). DoS는 가용성 공격.

대칭키 vs 공개키

구분대칭키공개키 (비대칭키)
키암호화 = 복호화 (같은 키)공개키 / 개인키 쌍
속도빠름느림 (수백~수천 배)
키 분배어렵다 (안전한 채널 필요)공개키는 공개해도 됨
키 개수 (n명)n(n−1)/22n
알고리즘AES, ChaCha20, (구) DES·3DESRSA, ECC, Diffie-Hellman
용도데이터 암호화키 교환, 전자서명
  • 공개키의 두 방향: 수신자 공개키로 암호화 → 수신자만 복호화(기밀성) / 송신자 개인키로 서명 → 누구나 공개키로 검증(인증·부인 방지).
  • RSA 는 큰 수의 소인수분해, ECC 는 타원곡선 이산대수 문제의 어려움에 기댄다. ECC 는 같은 안전도를 훨씬 짧은 키로 낸다(ECC 256비트 ≈ RSA 3072비트).
  • Diffie-Hellman: 도청되는 채널에서도 양쪽이 같은 비밀 값을 만들어 낸다. 단독으로는 상대를 인증하지 못해 중간자 공격에 취약 → 인증서 서명과 결합한다.

  • IV / Nonce 는 같은 키로 재사용하면 안 된다. 특히 GCM 에서 재사용하면 기밀성과 무결성이 함께 무너진다.
